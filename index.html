Aturan

Monitor ini hanya mengukur. Tidak mengubah mesin dan tidak menambah hipotesis atau varian. Semua metrik dihitung di browser dari data/signals.json dan data/raw/* sehingga bisa diaudit.

Sumber dan alur data

  • GitHub Action terjadwal menarik journal.json tiap mesin ke data/raw/<mesin>/. Versi lama disalin ke data/snapshots/ (satu per hari UTC, atau segera bila jumlah baris berkurang). Bila penarikan gagal, data lama dipertahankan dan mesin ditandai basi.
  • Setiap sinyal dinilai ulang dari candle Binance 1H (1m untuk kasus ambigu) dengan satu aturan seragam. Simbol Binance = aset + USDT, host sama dengan mesin (data-api.binance.vision lebih dulu).

Aturan grading (trade-sim.mjs dasar)

Dipilih karena identik di tn, tnv2, chatgpt, dan crypto. Dua varian lain menambah aturan manajemen order milik mesin, bukan aturan pengukuran: dseek membatalkan order yang belum terisi setelah 72 jam, tnv2c2 membatalkan order bila harga menyentuh TP sebelum pernah menyentuh entry. Monitor tidak memakai keduanya, jadi baris dseek/tnv2c2 yang dibatalkan mesinnya bisa berstatus lain di monitor dan muncul di Audit (a).

  1. Order limit terisi bila harga menyentuh entry. Bila candle dibuka sudah di sisi menguntungkan, terisi di open.
  2. Candle pengisi boleh menyentuh SL; bila ya, dihitung SL. TP di candle pengisi hanya dihitung bila terisi tepat di open.
  3. Candle yang menyentuh SL dan TP: urutan ditentukan data 1 menit; tanpa data itu, SL didahulukan.
  4. Candle yang memuat waktu sinyal tidak dipakai utuh; hanya lewat data 1 menit setelah waktu sinyal.
  5. Lewat batas waktu (due): tidak terisi = 0R; terisi = dinilai di close candle terakhir (bukan TP).
  6. Crypto: TP = tp (TP1 = tps[0]), level = level pertama kali terlihat (revisi di rev diabaikan). Baris ber-mode: pasar dinilai dengan aturan limit yang sama.

Status

TP
Terisi, lalu menyentuh TP. R = RR rencana.
SL
Terisi, lalu menyentuh SL. R = -1.
KEDALUWARSA_TERISI
Terisi tetapi belum TP/SL saat due. R dinilai di close, bisa positif atau negatif. Tidak pernah dicampur dengan TP.
TIDAK_TERISI
Entry tidak pernah tersentuh sampai due. R = 0, tidak dikenai biaya, tidak masuk win-rate.
OPEN
Belum selesai (belum due dan belum TP/SL), atau candle gagal diambil (lihat Audit).
NO_TRADE
Disaring mesin (hanya chatgpt). Tidak dinilai dan tidak dihitung sebagai sinyal.
TIDAK_VALID
Simbol kosong, angka tidak valid, urutan entry/SL/TP salah, atau Binance tidak punya candle untuk simbol itu. Tidak dihitung sebagai sinyal.

Metrik

  • N sinyal = semua selain NO_TRADE/TIDAK_VALID. Fill-rate = terisi ÷ (terisi + tidak terisi); OPEN tidak dihitung.
  • Win-rate (a) = TP ÷ (TP+SL). Win-rate (b) = (TP + kedaluwarsa dengan R sesudah biaya > 0) ÷ semua terisi. Win-rate hanya dari trade terisi. Interval = Wilson 95%.
  • Biaya = fee % per sisi + slippage % = % harga entry per trade terisi. R sesudah biaya = R − biaya% ÷ risiko%. (rumus sama dengan forward-lib.mjs)
  • Expectancy = rata-rata R sesudah biaya per trade terisi. CI95 = bootstrap 5000× dengan minggu kalender (Senin UTC) sebagai unit acak, seed tetap.
  • Profit factor dan max drawdown dari R sesudah biaya, urut waktu keluar.
  • Label sampel kecil bila trade terisi < 30.

Dedupe dan independensi

  • Kunci dedupe: aset + arah + t per mesin. Jumlah duplikat yang dibuang ada di Audit (d).
  • Basis "Semua baris" = semua baris setelah dedupe. Basis "Protokol" = meniru pickSignals() di forward-lib: baris tersegel, agen dan engine sesuai file protokol, setelah tanggal mulai, satu order aktif per koin. Hasil tetap dinilai ulang monitor. Mesin tanpa file protokol (crypto, grox) memakai semua baris.
  • Overlap fork: tn, tnv2, tnv2c2, dan chatgpt berbagi baris identik (engine yang sama) sampai fork masing-masing berganti engine. Baris ini ditandai kembar fork dan bukan bukti independen. Pada Konsensus, semua baris kembar dihitung sebagai satu sumber.

Syarat penilaian

Dibaca dari forward-protocol*.json tiap mesin (bukan di-hardcode). Mesin "belum layak dinilai" sampai trade terisi dan jumlah minggu memenuhi syarat; setelah itu lulus bila batas bawah CI95 expectancy sesudah biaya > 0. Angka sebelum itu hanya kemajuan, bukan bukti.

Keterbatasan

  • grox: jurnalnya hanya di localStorage browser pemiliknya sehingga tidak bisa diambil. Ditandai "tidak tersedia". Opsi: pasang extras/grox-journal.yml di repo grox agar Action menulis data/journal.json dengan engine yang sama, lalu set "aktif": true untuk grox di config.json.
  • crypto tidak punya hasil/R, jadi status_mesin kosong dan tidak ikut audit (a). Seluruh nilainya dari penilaian monitor. Due = 3 hari.
  • Aset saham/ETF tokenisasi (mis. NVDAB) dinilai bila Binance spot punya pasangan <aset>USDT; bila tidak, TIDAK_VALID.
  • Semua hasil bersifat teoretis berbasis candle Binance, bukan eksekusi nyata. Sampel masih sedikit minggu, jadi CI lebar.
